# DotAIOS v1.3 Plan

DotAIOS v1.3 should make the system useful across agents without losing the local-first, simple-files product shape.

## Product Principle

Prefer visible, inspectable, user-controlled flows over hidden automation. Add power through small composable surfaces:

- CLI commands that explain what they do.
- MCP tools for clients that support tools.
- Markdown skills and docs that any agent can read.
- No background daemon unless a later workflow truly needs one.

## Priority 1: Google Workspace Assisted Beta

Goal: make Gmail/Calendar useful while being honest that Google OAuth still has friction.

Current local shape:

- `dotaios google setup`
- `dotaios connect google`
- `dotaios google status`
- `dotaios google inbox`
- `dotaios google agenda`
- `dotaios google drive`

Next improvements:

- Add friend-facing setup script with screenshots or a short checklist.
- Prefer `gws auth login --readonly --services gmail,calendar,drive`.
- Keep write actions out of the wrapper until beta trust is earned.
- Later: evaluate a hosted/verified OAuth app for a true "Sign in with Google" path.

## Priority 2: MCP Surface

Goal: make DotAIOS usable by MCP-capable agents without forcing them to read bridge files manually.

Current local shape:

- `packages/mcp/src/server.mjs`
- `dotaios-mcp` bin in the root package
- `dotaios mcp status`
- `dotaios mcp install --dry-run --agent claude|codex|cursor|gemini`

Initial tools:

- `read_context`
- `search_memory`
- `search_vault`
- `list_projects`
- `log_event`

Rules:

- Do not mutate MCP client config automatically yet.
- Keep MCP separate from `dotaios activate`.
- Use stdio transport.
- Keep SDK dependencies out of the root CLI unless a published `@dotaios/mcp` package needs them.

## Priority 3: Memory and Indexing

Use external projects as patterns, not stacks to copy wholesale.

### agentmemory

Borrow:

- MCP-first memory server shape.
- Cross-agent memory as the common layer.
- Auto-capture hooks later.
- Viewer/dashboard idea later.

Do not adopt now:

- Running server requirement.
- Larger dependency surface.
- Hook automation before beta trust.

### CocoIndex

Borrow:

- Incremental indexing.
- Delta-only recompute.
- Data lineage and source provenance.

Do not adopt now:

- Python/Rust indexing stack.
- External stores by default.

### Synthadoc

Borrow:

- Compiled Markdown wiki.
- Frontmatter.
- Wikilinks.
- Audit trail.
- Lint/scaffold/check workflow.

Do not adopt now:

- Python/provider complexity.
- LLM compilation step as a required install path.

### Karpathy LLM Wiki

Borrow:

- Source -> wiki -> index/log shape.
- Human-readable durable knowledge.
- Explicit provenance over hidden embedding state.

Next DotAIOS version:

- Add generated `vault/wiki/_index.md`.
- Add `vault/log.md` or memory-backed log summary.
- Keep raw sources under `vault/raw/`.

### Browserbase AutoBrowse

Borrow:

- Evaluate -> trace -> improve -> publish loop.
- Skill self-improvement workflow.

Later DotAIOS idea:

- `dotaios skill audit`
- `dotaios skill trace`
- `dotaios skill publish --dry-run`

### Matt Pocock Skills

Borrow:

- Small, composable skills.
- Strong setup checks.
- Test-first / diagnose / refactor loops.
- Skill instructions that are practical rather than grand.

Next DotAIOS version:

- Add frontmatter to built-in skills.
- Add `skills/_registry.json` validation for required bins, schedule type, and approval level.

## What Not To Do Yet

- Do not add cloud sync.
- Do not add vector DBs.
- Do not make Google writes easy before reads are trusted.
- Do not auto-edit MCP client config until paths are tested in real clients.
- Do not absorb external repos as dependencies unless they reduce real product friction.

## Release Shape

Keep `dotaios@1.2.1` as the public stable beta.

Prepare `1.2.2` locally until:

- Google setup flow is friend-testable.
- MCP server works in at least one real client.
- Docs include a one-page friend beta script.
- `npm test`, `npm run smoke`, `npm run check`, and pack checks pass.
